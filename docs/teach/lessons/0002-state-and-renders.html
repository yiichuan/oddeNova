第二课：State 与重新渲染 入门

系列：React 基础 · 术语表 · 预计用时：12 分钟

1. 你将学到什么

上一课我们学到：组件是返回 JSX 的函数，props 从父到子传递数据。但 props 是只读的——如果组件需要自己管理会变化的数据，就需要 state。

本课你将学到：

  • useState 如何工作：声明、读取、更新
  • 更新 state 如何触发重新渲染
  • 函数式更新与批处理
  • state 是"按组件位置"记忆的——为什么这很重要

2. useState：给组件添加记忆

useState 是最基本的 hook。它让组件"记住"一个值，并在该值变化时触发重新渲染。

import { useState } from 'react'

function Counter() {
  // 声明一个 state 变量，初始值为 0
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      点击了 {count} 次
    </button>
  )
}

解构这行代码：

  • useState(0) — 调用 hook，传入初始值 0
  • count — 当前值（本次渲染中的快照）
  • setCount — 更新函数，调用它会触发重新渲染
关键心智模型：count 不是"变量"——它是本次渲染的快照。每次调用 setCount，React 会用新值安排一次重新渲染，整个组件函数从头重新执行，count 获得新值。

3. 更新 State 的正确方式

直接更新 vs 函数式更新

当你需要基于当前值计算下一个值时，有两种写法：

// 方式一：直接传入新值
setCount(count + 1)

// 方式二：传入一个函数（函数式更新）
setCount(prev => prev + 1)

区别在于"批处理"场景。React 为了性能，会把同一次事件中的多次 state 更新合并为一次重新渲染：

function handleTripleClick() {
  setCount(count + 1)  // 用的是本次渲染的 count
  setCount(count + 1)  // 还是同一个 count！
  setCount(count + 1)  // 同上
  // 结果：count 只增加了 1，而不是 3
}

function handleTripleClickFixed() {
  setCount(prev => prev + 1)  // prev 是最新的值
  setCount(prev => prev + 1)
  setCount(prev => prev + 1)
  // 结果：count 增加了 3
}
规则：如果新 state 依赖前一个 state，总是用函数式更新 setX(prev => ...)。

对象的更新

State 不会自动合并——你必须用展开语法（spread）手动保留其他字段：

const [form, setForm] = useState({ name: '', email: '' })

// 错误：丢失了 email
setForm({ name: 'Ada' })

// 正确：保留 email
setForm(prev => ({ ...prev, name: 'Ada' }))

4. 渲染周期：State 变化 → 重新渲染

当调用 setCount 时，React 做以下事情：

  1. 将新值排入更新队列
  2. 安排一次重新渲染（可能批处理多次更新）
  3. 重新调用组件函数，拿到新的 JSX
  4. 将新 JSX 与旧 JSX 比较（协调过程）
  5. 只把有差异的部分提交到真实 DOM
// 第 1 次渲染：count = 0
//   JSX: <button>点击了 0 次</button>

// 用户点击 → setCount(1)

// 第 2 次渲染：count = 1
//   JSX: <button>点击了 1 次</button>

// React 比较两棵树，发现文本内容变了
// 只更新 DOM 中的文本节点，按钮元素本身不变
渲染 ≠ DOM 操作：每次重新渲染都会调用组件函数，但 React 不一定会操作 DOM。如果 JSX 没变化，DOM 就不动。这就是虚拟 DOM 的价值——最小化真实的 DOM 操作。

5. 从 oddeNova 看真实代码

oddeNova 的 App.tsx 中有大量 state 声明。看几个真实的例子：

// src/App.tsx（简化）
const [demoStep, setDemoStep] = useState(0)
const [isMoodLoading, setIsMoodLoading] = useState(false)
const [rollbackPrefill, setRollbackPrefill] = useState('')
const [showApiKeyModal, setShowApiKeyModal] = useState(() => {
  try { if (window.self !== window.top) return false } catch { return false }
  return !hasApiKeyConfigured()
})

注意最后一个——初始值不是简单字面量，而是一个函数。这叫惰性初始化：

// 普通初始化：每次渲染都会计算初始值（即使只在首次用到）
const [val, setVal] = useState(expensiveComputation())

// 惰性初始化：只在首次渲染时执行函数
const [val, setVal] = useState(() => expensiveComputation())

oddeNova 用惰性初始化来检测是否在 iframe 中、是否已配置 API key——这些检查只需要做一次。

更简洁的例子：useIsMobile

src/hooks/useIsMobile.ts 是一个完美的小例子，展示了 state + effect 的基本模式：

// src/hooks/useIsMobile.ts
export function useIsMobile(): boolean {
  const [isMobile, setIsMobile] = useState(
    () => window.matchMedia('(max-width: 768px)').matches
  )

  // 惰性初始化：首次渲染时检测一次窗口大小
  // 后续变化交给 effect 监听

  return isMobile
}

这里 isMobile 是布尔 state，初始值通过惰性初始化从 matchMedia 获取。组件使用 useIsMobile() 就能在窗口大小跨越断点时自动重新渲染。（effect 部分下一课讲。）

6. State 是按位置记忆的

React 通过组件在树中的位置来关联 state，而不是通过组件名。这意味着：

// 两个 Counter 是独立的，各自有自己的 count
function App() {
  return (
    <>
      <Counter />   {/* 位置 1：count = A */}
      <Counter />   {/* 位置 2：count = B */}
    </>
  )
}

对于列表中的组件，React 用 key prop 来区分：

// 如果 items 顺序变了，key 帮助 React 追踪哪个是哪个
{items.map(item => (
  <TodoItem key={item.id} item={item} />
))}
常见陷阱：用数组索引作为 key，当列表重排时 state 会"跟错"组件。始终用稳定唯一的 ID 作为 key。

7. 检查你的理解

测验：State 与重新渲染

调用 setCount(count + 1) 连续三次（同一事件处理函数中），count 最终增加多少？

正确！三次调用用的是同一个 count（本次渲染的快照），所以三次都计算为 0 + 1 = 1。React 批处理后只渲染一次，count 变为 1。要增加 3 次，需要用函数式更新：setCount(prev => prev + 1)。

useState(() => initFunction()) 中的函数何时执行？

正确！传入函数给 useState 是惰性初始化——React 只在首次渲染时调用该函数获取初始值，后续渲染直接忽略它。这避免了每次渲染都做不必要的计算。

两个同名的 <Counter /> 组件并排放置，它们的 state 是共享的吗？

正确！React 按位置而非名字关联 state。两个 <Counter /> 在不同位置，各有自己的 state。要共享 state，需要"状态上提"到共同父组件——后续课程会讲。
