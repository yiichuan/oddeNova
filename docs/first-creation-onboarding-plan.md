# oddeNova 新手指引方案 v3：第一次创作

日期：2026-11-09

状态：桌面端与手机端均已实现，取代旧的印象曲改编练习（`docs/new-user-onboarding-plan.md`，已归档）。

## 1. 目标

新用户进入工作室后，用四句话从零写出一首约 30 秒的曲子，学会「说一句想法 → 听到结果 → 接着说」。
全程预制，不调用模型、不跑 agent loop、不消耗额度；声音由真实 Strudel 引擎播放。

印象曲照常作为历史会话保留，不再参与新手指引。练习从一个空白会话「我的第一次创作」开始。

## 2. 流程

邀请卡（0/4）：「用 4 个步骤，体验如何通过和 oddeNova 对话，从零写出一首曲子。」→ 开始／稍后再说。

| 步 | 输入框里的预设 | 生成后 |
| --- | --- | --- |
| 1 | 一段简单的节奏 | 聚焦整个代码面板，简短说明「这是它写出的代码」 |
| 2 | 钢琴写一段旋律，加上去 | 代码自动滚到底部，框出新增的 `PIANO` 层并说明 |
| 3 | 添加一些背景渲染 | 同上，框出新增的 `PAD` + `TEXTURE` |
| 4 | 扩展成一段 30 秒的曲子 | 弹出「你已经完成第一次创作」 |

每一步的发送都和旧流程的发送步骤一样：聚光灯打在真实输入框上，预设文字锁定在框内，用户点真实的发送键（卡片里的发送图标与之等效）。

发送后在对话流里按真实回合的形态依次出现：

1. 用户消息；
2. 思考指示器 + 流式「构思」文字（mock，约 1.6 秒）；
3. 「编排音乐」→「准备播放」；
4. 代码写入编辑器并自动播放，回复消息带代码与修订记录。

生成期间遮罩撤掉，方便看对话流；输入框的停止键可中断，中断后重新发送会先清掉残留的半截回合。

完成弹窗：「先说出想法，再听听变化，就能一步步做出自己的乐曲。练习作品已保留在历史中。」
按钮为「创作一首新的」和「继续改这首」（音乐继续播放、聚焦输入框），并附注「刚才使用的是演示示例……」。
完成后用户在练习会话里发出的第一条真实指令，同样视为完成，并计入漏斗。

### 手机端（5 步）

邀请卡（0/5）：「用 5 个步骤……」，按钮为「稍后再说」和「开始」。

1～4 步：卡片在输入框上方，预设文字锁定在框内，用户点真实的发送键。发送后引导整个隐去，回合在对话流里照常展开。代码提交时会自动播放，该回复的 widget 随之亮起为「正在播放」。约 1.8 秒后，下一步的卡片出现。手机端没有每步之后的代码说明。

5 步：第 4 段开始播放后，卡片挂在右上角代码按钮下方：「音乐背后是什么？点击右上角的代码按钮看看。」
用户点开代码窗口后，遮罩框住窗口内的代码区，代码用 3.2 秒平缓滚到底。说明卡片放在代码区下方（放不下时放到上方），文案为：「你说的每一句话都变成了这段代码，正是这些代码在驱动音乐的播放……」。
点「知道了」关闭代码窗口，回到对话页，弹出「你已经完成第一次创作」。按钮为「继续改这首」（左）和「创作一首新的」（右，强调色）。

跨越手机／桌面断点时，练习按当前布局继续：桌面的解释步换成手机的下一轮；手机的代码窗口步换成桌面的完成弹窗。

## 3. 资产

`onboarding/first-creation-v1/step-{1..4}.{zh,en}.strudel.js`：四段完整脚本，中英文只有注释不同。
对话文案（指令、构思、回复）在 `src/onboarding/first-creation-copy.ts`，每轮新增的音层在 `first-creation-case.ts`。

108 BPM（`setcps(0.45)`），一个 cycle ≈ 2.22 秒；第 4 段用 14 个 cycle 的 mask 编排，约 31 秒。

## 4. 实现

| 模块 | 作用 |
| --- | --- |
| `first-creation-case.ts` / `first-creation-copy.ts` | 案例数据、内容哈希（区分语言、检测资产变动） |
| `first-creation-state.ts` | 步骤 `compose-1 → explain-1 → … → compose-4 → done` 的 reducer 与按账号存储（`oddenova_first_creation_v1:`，guide_version 3） |
| `first-creation-session.ts` | 建空白练习会话、统计已写入的回合、清理半截回合、恢复检查 |
| `use-cloud-settled.ts` | 账号级「已完成／已跳过」云端标记（与手机端共用同一标记） |
| `useFirstCreation.ts` | 引导主逻辑：邀请、开始、恢复、回合 mock、交接 |
| `FirstCreationTour.tsx` | 桌面聚光灯与卡片 |
| `MobileFirstCreationTour.tsx` | 手机卡片、代码按钮与代码窗口步骤 |

回合通过与真实 agent 回合相同的会话写入接口（`addUserMessage`、`appendToLastReasoning`、`addProgress`、`addAssistantMessage`、`setCurrentCode`）和同一个 loading 集合产生，因此练习结束后就是一段普通对话，模型接手时看到的上下文与用户所见一致。引导卡片的文字不写入消息。

新增代码的定位用 `@layer` 标记解析，不依赖行号。

## 5. 恢复与边界

- 登录后按当前账号的本地进度和云端完成／跳过记录判断是否自动邀请。游客进度独立，游客的自动邀请仍取决于浏览器的首次访问标记。
- 刷新或离开练习会话时，中断进行中的回合；重新进入时出现「继续上次练习」。恢复时以会话里实际存在的回合为准，修正进度，并清掉半截回合。
- 练习会话被删除、代码被改动或资产版本不一致，就提示无法接着演示，只提供重新开始，不覆盖现有内容。
- 引导步骤卡上不提供退出入口（沿用 b36abaf 的决定）。拒绝邀请后，指引一次「更多 → 新手指引」入口。

## 6. 旧方案的清理

旧的印象曲练习（`useOnboarding`、`MobileOnboardingTour`、`intro-piano-v1` 资产等）已删除。仍留着的残余：

- `ConversationView` 的 `guidedReply` 和 `CodePanel` 的 `guidePlay`：可选参数，已无人传入，可以连同各自的测试一起删除。
- `i18n.ts` 里旧流程的文案：其中 `ONBOARDING_PRACTICE_INTRO_ZH` 仍被问候语字体子集脚本引用，删除前要一并调整 `scripts/build-greeting-font-subset.ts` 及其测试。
