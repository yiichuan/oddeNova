# 移动端新手指引执行方案

状态：代码已实施，自动化检查通过；开发者人工验收（真机、听感、视觉）尚未进行。见第六节实施记录。

适用基线：当前已实现的桌面端六步指引，以及 `intro-piano-v1` 练习资产。原始产品方案见 [新手操作指引方案](./new-user-onboarding-plan.md)；本文件针对手机的交互与布局补充执行方案。现有实现与旧方案不一致的地方，以本文明确说明的当前代码事实为起点，不重做桌面端。

## 一、目标

手机用户在约 1～2 分钟内完成一次真实操作练习：找到播放入口、发送预设指令、在回复里试听改变、开始自由创作。

用户只需打开一次完整代码窗口。后半程在对话页完成，不要求反复往返代码窗口，也不要求阅读代码。继续使用已完成的预设音乐与回复，练习不调用模型或 agent loop。

本轮交付是执行方案文件。后续实施范围包括移动端呈现、目标定位、播放接入、键盘与遮挡处理及针对性测试；不包含新音乐案例、跨设备进度同步或桌面端流程重做。

## 二、设计原则

1. **教真实入口。** 首次试听教会右上角代码窗口入口，改编试听教会回复下方的播放按钮；不另做只在教学期间存在的主播放器。
2. **一个画面只突出一件事。** 提示卡使用短句和明确动词，不把多段说明、多个试听按钮和代码同时挤在屏幕上。
3. **让触控操作容易。** 按钮有足够点击面积，主要操作靠近当前目标；说明中的小图标只用于识别，不作为第二个可点按钮。
4. **先听变化，再按需看代码。** 音层名作为补充信息，不成为完成引导的门槛。
5. **共享业务，区分呈现。** 两端使用同一练习、消息、播放判定、会话和进度；布局、文案、操作入口可以不同。
6. **延续已有视觉。** 遵循 `.impeccable.md`：清楚的对齐与层级、平整的对话界面、少量有用途的强调；不新增装饰性玻璃卡片或大片动画。

## 三、现状与实现依据

以下来自代码阅读，未启动开发服务器或浏览器进行视觉验证。

| 当前事实 | 对移动端方案的影响 |
| --- | --- |
| `useIsMobile.ts` 使用宽度不超过 460 CSS px 的断点 | 本次沿用断点；横屏跨过断点可能切回桌面布局，需要处理进行中的引导，不能假设手机一直命中移动布局 |
| 手机工作室为顶部导航、中部 `ConversationView`、底部 `ChatInput` | 对话是主操作空间，提示应围绕消息和输入区组织 |
| 右上角 `mobile-code-key` 打开 `mobile-code-sheet`；代码窗口隐藏时仍挂载 | 首次原版没有可直接复用的回复版本播放器，先教实际代码窗口入口；不能卸载窗口影响编辑器／音频绑定 |
| `App.tsx` 当前在两次试听和 `view-change` 自动打开代码窗口，其余步骤自动关闭 | 这是初步移动适配，本次要替换为明确的移动呈现控制，避免每一步自动开关窗口 |
| `OnboardingTour.tsx` 复用桌面浮动提示卡，仅在手机改变宽度 | 需要独立移动呈现；不能只缩小桌面浮层 |
| 卡片定位用 `innerWidth/innerHeight`，现有内联可点击图标约 18 px | 需要可见视口、安全区与触控尺寸适配；手机不复用内联小按钮 |
| 初始练习消息是 greeting，不携带 revision；`draftRevision` 仅在草稿不同于基准时出现 | 不假定原版 greeting 下已有版本播放按钮，也不为教学伪造一条修改记录 |
| mock 回复有实际 revision，`CodeDiffView` 有 `data-code-diff-play`、`data-code-diff-toggle` 和 `data-diff-group` | 改编试听与局部代码查看可在回复内完成 |
| 回复播放器经 `handlePlaySegment` 播放具体版本，桌面监听则按实际 `activeCode` 和播放头认定已听 | 接入时要对准练习回复及同一代码，并复用原来的 5 秒监听，不能新增墙钟计时 |
| `ChatInput.presetLock` 已支持只读预设和真实发送按钮 | 直接预填现有指令；处理自动 focus，避免只读练习唤起软键盘 |
| `useLayout` 已有键盘抬升；`useVisualViewport` 已读取可见视口 top/height | 优先扩展既有能力，不重复计算抬升，不让卡片和输入区各自移动一次 |
| 进度当前按 owner 存在本地 localStorage，六步状态版本为 2 | 两端同浏览器共享进度；不能宣称已有跨设备完成状态同步 |

### 保持的教学内容

唯一指令继续使用 `intro-piano-case.ts` 中的现有文本：

> 保留原来的背景和弦，只在开头 10 秒加一串清脆的电钢琴音符，跟着和弦一颗颗弹出来。

改编仍为保留原 `horizon` 并新增 `horizon_intro`，两版均听 0～5 秒。不修改案例正文／音乐以缩短手机版文案，否则会改变案例内容校验值。只给引导提示新增移动端文案。

`onboarding/intro-piano-v1/README.md` 目前仍将听感验收列为未完成；实施时核对是否已有人工验收记录，不能因为桌面指引完成就宣称手机扬声器听感已经通过。

## 四、流程与实施引导

### 4.1 总体流程

每出现一个新的引导弹窗就算一步，邀请为第 0 步，共 7 步：

邀请（0/7）→ **1/7 打开代码窗口** → **2/7 窗口内试听** → **3/7 关闭窗口** → **4/7 发送预设** → **5/7 看回复** → **6/7 听改编** → **7/7 完成**。

这些是移动端的呈现编号，继续使用现有六个语义状态。

| 移动步骤 | 现有状态 | 当前页面与主要目标 |
| --- | --- | --- |
| 1/7 打开窗口 | `listen-original`（窗口关闭、未听） | 对话页右上角代码键 |
| 2/7 窗口内试听 | `listen-original`（窗口打开、未听） | 代码窗口真实播放键 |
| 3/7 关闭窗口 | `listen-original`（已听） | 代码窗口关闭键；窗口已关的恢复场景显示「继续」 |
| 4/7 发送预设 | `send-instruction` | 底部真实输入框及发送键 |
| 5/7 看回复 | `read-reply` | 练习回复 |
| 6/7 听改编 | `listen-adapted` | 回复下方播放键 |
| 7/7 完成 | `view-change` 或 `done` | 完成面板，代码差异可选展开 |

### 4.2 邀请与恢复

邀请沿用现有资格与时机判断，不在本次重写登录、游客继承、postpone 或首次访问规则。手机进入前要先关闭导航抽屉，等待登录／导入等优先流程结束。

邀请为屏幕居中的弹窗，宽度与手机端确认弹窗一致（最大 320 px，两侧 32 px），圆角与内边距与后续引导卡一致，左上角显示「0/7」，文案与桌面端一致，只把步骤数改为 7：

> 0/7
>
> **oddeNova：欢迎！**
>
> 用 7 个步骤，体验如何通过和 oddeNova 对话来创作乐曲。
>
> **开始**（左，主题色文字）　稍后再说（右）

点击开始复用现有练习会话创建逻辑。邀请本身不停止音乐；真正开始练习才切换。恢复提示（含无法继续）使用与邀请相同的居中弹窗和宽度，底部为通栏圆角矩形按钮（圆角 6 px），从上到下「继续」（主题色底）、「重新开始」「稍后再说」（灰色底，文字为主文字色）；无法继续时为「重新开始」（主题色底）与「稍后再说」。不自动播放。

### 4.3 阶段 1：教会“在哪里播放”

**A. 对话页定位入口**

- 开始后停留在对话页，代码窗口默认不自动打开。
- 高亮右上角实际代码入口；提示卡挂在高亮区域正下方、与其右对齐，两行依次为「1/7」、「点击打开代码窗口，代码和播放都在这里。」，右上角为「退出引导」。
- 此时原版试听条件尚未完成，不显示可用的下一步。保留跳过。
- 用户点击入口后进入 B；不需要额外持久化一个“打开窗口”步骤。

**B. 窗口内试听**

- 代码窗口打开后，目标变为其中真实播放键。等窗口尺寸稳定、目标可见后再画高亮。
- 只高亮播放键，右上角关闭键跟随遮罩变暗、不可点。提示卡挂在播放高亮正下方、与其左对齐（代码窗口为其让出底部空间），依次为「2/7」、「点击播放，听开头 5 秒，留意铺开的背景和弦。」、进度条，右上角为「退出引导」。
- 保留现有音色准备、重试、播放头进度和 5 秒结束判定。正在准备时真实目标也要不可触发，不能只把卡片按钮禁用。
- 开始播放后真实播放键（此时显示暂停）失效，不能暂停，自动播满 5 秒后由引导停止；因此本步不显示「未播满 5 秒」提示。切后台等外部中断仍会取消本次试听。
- 不聚焦编辑器，不弹出键盘；代码可看但本步不允许编辑，避免改变预设基准。该限制仅用于当前练习。
- 本步隐藏／屏蔽时间轴跳转、导出、分享等无关操作；保留真实播放和窗口关闭入口。

**C. 返回对话**

- 听完后高亮现有关闭键；提示卡挂在关闭键高亮正下方、与其右对齐，两行依次为「3/7」、「听过原版了，点击关闭代码窗口，试着改一改。」，右上角为「退出引导」。
- 用户关闭窗口且 `originalHeard` 为 true，关闭窗口并调用一次现有 `next()`，进入阶段 2。
- 未听完就关闭：保持 `listen-original`，回到 A 的入口提示，不标记已听、不自动重新打开、不丢失已确认的事实。
- 本阶段内关闭窗口时停止仍在播放的试听；此行为只在引导期间生效，不改变普通工作室关闭窗口的播放规则。
- 原版已听完、窗口已关的恢复场景：屏幕居中弹窗（宽度同第 0 步，布局同第 7 步），依次为「3/7」、「原版已经听过了，接着试试改一改。」、通栏主题色圆角矩形按钮「继续发送想法」，右上角「退出引导」；无需强迫重开窗口再关一次。

这样用户学会真正的入口，也只需一次完整代码窗口往返。

### 4.4 阶段 2：用真实输入框发送

- 保持对话页，预设自动填入已有 `ChatInput.presetLock`。
- 提示卡紧贴输入区上方，布局与前面的提示卡一致，依次为「4/7」、「要求已经填好，点击发送试试看。」、载入／失败状态。输入框左下角显示「引导练习 · 预设示例」（桌面端相同）。
- 预设只读，不自动 focus textarea；点击只读区域也不主动 focus。不通过禁用整个表单来阻止键盘，以免发送键无法使用。
- 高亮区域可以包含输入框，但唯一主要操作为真实发送键；不在卡片再放一个发送副本。
- 输入框允许完整阅读预设；较长英文可内部滚动，不裁掉发送键。示例发送不要求打开键盘。
- 点击发送复用 `sendPreset()`，呈现现有载入／回复流程，禁用重复点击；继续提供退出。
- 出错停留本阶段并提供重试。已有 mock 写入后恢复时按现有幂等检查前进，不再次追加消息。
- 想自由输入时使用明确的「退出引导」入口；退出后才恢复编辑并进入真实 AI 流程，不把任意文字送给固定 mock。

### 4.5 阶段 3：原地看回复、听改编

**A. 看回复（`read-reply`）**

- 将特定 `replyMessageId` 对应的回复和版本操作栏一起滚动到可见范围，输入区暂不作为可交互目标。
- 提示卡挂在回复高亮区域下方、与回复同宽，依次为「5/7」、「背景和弦保留了，开头多了一串琴音。」、底部「听听改编」（主题色文字按钮，无背景），右上角为「退出引导」。回复下方空间不足时卡片保持在屏幕内。
- 主操作为「听听改编」，调用一次 `next()` 进入 `listen-adapted`；这个按钮只切换教学状态，不自动播放。

**B. 按真实版本按钮播放（`listen-adapted`）**

- 高亮该回复的 `data-code-diff-play={replyMessageId}`。提示卡挂在播放高亮下方、与其右对齐，依次为「6/7」、「点回复下方的播放，听 0～5 秒里多出来的琴音。」、进度条、底部（听完后出现）「听到了，继续」（主题色文字按钮，无背景），右上角为「退出引导」。
- 保持代码窗口关闭，不把全局编辑器播放键作为手机版目标。
- 点击真实回复播放键后，通过练习限定的接入使用该 revision 的完整改编代码；沿用现有 `watchListening`，以 `activeCode` 匹配后才计时。
- 本步开始播放后，该按钮（此时显示停止）失效，自动播满 5 秒后由引导停止，因此不显示「未播满 5 秒」提示。只在本步生效，普通消息播放器与桌面代码窗口的播放／停止语义不变。
- 五秒结束后显示「听到了，继续」，调用现有 `next()` 进入 `view-change`，即移动阶段 4。
- 加载失败或播放失败时提供可见的重试入口，切后台等中断后由用户重听，不让“下一步”提前放行。

看回复与听改编在同一处页面完成（5/7、6/7），避免看完回复又打开代码窗口。

### 4.6 阶段 4：完成与可选差异

手机将 `view-change` 和 `done` 投影到同一个完成弹窗（7/7），不再要求额外一页代码教学。弹窗居中，宽度、圆角与内边距与第 0 步相同：

> 7/7
>
> **你已经完成第一次改编**
>
> 原来的背景还在，多了一串开场琴音。下次也可以这样描述你想要的变化。练习作品已保留在历史中。
>
> ［原版 · 5s］［改编 · 5s］（桌面端相同；播放时数字从 5 倒数到 0，「s」位置不动）
>
> （主题色圆角矩形按钮，通栏）**继续改这首**
>
> （灰色圆角矩形按钮，通栏）创作一首新的
>
> （灰色圆角矩形按钮，通栏）查看修改部分

- 主按钮调用现有 `keepEditing()`；次操作调用 `createNew()`。现有 `finish` 能从已交付的活动状态结束流程，因此无需连调两次 `next()` 或重写六步 reducer。
- 手机完成操作的可用条件为已交付、两段必经试听已完成。异常旧记录先落回缺失的必要步骤，不靠较宽松的底层 finish 条件跳过实际体验。
- 在 `view-change` 退出后现有 finish 将持久状态设为 `done/completed`；从桌面 `done` 恢复到手机也显示同一面板。
- 「查看修改」打开当前回复已有的 `CodeDiffView`，定位其中 `horizon_intro` 分组，附「原背景和声 horizon 保持原样」。不自动打开完整代码窗口。
- 差异展开后高亮只框住展开的代码 widget（恢复正常尺寸，不放大），提示卡挂在其下方、与其同宽：说明一句，底部左侧「收起修改」、右侧「继续改这首」（主题色），均为无背景文字按钮。点击「收起修改」返回完成弹窗。
- 两版 5 秒对比按钮常驻在说明下方，复用 `playCompare()`。不在本次新增连续 A/B 播放能力。
- 打开「查看修改部分」时停止比较播放。切换、离开、完成时停止比较播放，保留改编版草稿。
- 保存状态复用真实 `persistent` 判断，接在说明正文之后（同桌面端）。
- 点击继续后先关闭引导与任何教学覆盖层，再交回输入焦点。移动浏览器未唤起键盘时保留正常输入框，不循环强制 focus。

### 4.7 版面与触控规格

**一套移动引导外壳，三种摆放方式：**

| 场景 | 提示位置 | 需要留出的空间 |
| --- | --- | --- |
| 邀请、恢复、完成 | 屏幕居中弹窗（最大 320 px），过高时弹窗内滚动 | 可见视口内上下各留 12 px |
| 右上入口、窗口播放、回复试听 | 底部短提示条与目标高亮 | 对话滚动区域／代码窗口真实布局为提示条预留高度，不靠遮住内容解决 |
| 发送预设 | 输入区上方的短提示 | 提示、预设正文、发送键要能同时操作；不额外再放一个底部面板 |

- 移动端高亮区域不加主题色描边，只靠遮罩挖空表示目标。
- 移动端各引导提示卡的「退出引导」放在卡片右上角，与步骤编号同一行（44 px 高点击区）；继续类按钮单独放在卡片底部一行。
- 左右边距以现有移动页面 12 px 为起点；使用已有主题变量、字体和圆角，不加入独立视觉主题。
- 提示正文通常一两句；进度显示「1/7」等。跳过保持可见，避免每一步都同时放上一步、下一步、播放副本和其它次按钮。
- 指引动作和被引导的播放、发送、关闭入口，点击区域至少 44 × 44 CSS px；视觉图标可以更小。扩展区域不能与相邻复制／展开按钮重叠。
- `CodeDiffView` 目前播放区域宽度为 `w-7`；需明确增加手机触控面积，而不是只加一层会吞掉邻近点击的透明伪元素。
- 引导卡片浮在页面之上，不为卡片预留或改变页面／代码窗口的布局，步骤切换和退出引导都不引起页面重排。卡片在目标稳定（连续 3 帧不动）且尺寸测量完成后才显示，不在临时位置先画一次；目标下方放不下时放到上方，两边都放不下时保持在屏幕内。回复下方播放键的 44 px 点击区用不占布局的透明扩展实现，widget 本身尺寸不变。
- 向目标所在的滚动容器滚动一次，并计算提示条遮挡；用户自行滚动时允许阅读，不持续强拉回目标。
- 短视口或大字号下，采用内容可滚动、操作栏保留的布局；不要求回复、差异和提示全文必须同时显示。
- 屏幕阅读器能按提示→真实目标→继续／跳过的顺序操作。对话阅读阶段不把整条消息设为不可滚动的“洞”；遮罩应允许目标区域的阅读滚动。
- 开启代码窗口时避免两个互不相知的模态焦点域；手机提示放在当前活动面板的可访问区域内，隐藏背景控件不可被 Tab 访问。退出恢复焦点。
- 尊重减少动态效果。定位跟随可见区域变化，不依赖持续的卡片飞行动画。

### 4.8 键盘、视口和中断

- 默认路径不需要键盘。预设阶段避免 `handleCardClick`、focusTrigger 等通路间接聚焦只读 textarea；不能只设置 readOnly 就认为键盘问题已解决。
- 复用／扩展 `useVisualViewport`，明确 overlay 坐标和 `getBoundingClientRect()` 的换算，处理可见区域的 top/left/width/height；API 缺失时回退布局视口。
- 底部输入已有 `keyboardHeight` 抬升时，提示位置以实际输入框矩形为准，不再次减一次键盘高度。地址栏变化与键盘事件都重新计算可用空间。
- 将 `navDrawerOpen` 纳入手机引导可呈现条件，避免抽屉上再叠教学层；从菜单打开引导时先关抽屉。代码窗口是阶段 1 的合法教学场景，不能一概视为阻塞。
- 页面退到后台或音频中断时停止教学播放、取消本次未完成试听的判定，返回后保留步骤并由用户重听；已确认的听完状态保留。特别防止现有 tail 定时回调在中断后迟到推进。
- 切会话、切账号、离开工作室、跳过时复用取消逻辑，迟到加载／播放结果不得操作新的页面。
- 同一次加载内跨越 460 px 断点时，暂停播放、保留语义状态、重算目标，以对应布局继续。不要因横屏重建练习或清零进度。
- 在手机的阶段 1 关闭教学窗口会按本节规则前进；普通浏览器后退不应被改写为全局的引导下一步。已有返回／关闭入口按应用现有导航语义处理，不增加伪造历史项。

### 4.9 目标定位与状态兼容

**独立移动目标解析器。** 目标必须在当前可见布局范围内，不能全局取第一个同名选择器；窗口隐藏但仍挂载，单靠节点存在不能证明可操作。

建议使用以下语义定位，并由组件主动暴露需要的展开接口：

| 目标 | 现有依据／建议补充 |
| --- | --- |
| 打开音乐窗口 | `mobile-code-key`，增加明确 onboarding target |
| 关闭音乐窗口 | 现有关闭键，补充语义 target |
| 原版播放 | 当前可见代码窗口内的 `data-onboarding-target="play"` |
| 预设发送 | `composer` 内真实 submit，补充 send target |
| 改编回复 | `data-message-id={replyMessageId}` |
| 改编播放 | 该回复内的 `data-code-diff-play={replyMessageId}` |
| 局部变更 | 该回复已展开后的 `data-diff-group="horizon_intro"` |

通过 React props／回调控制差异展开和读取目标状态，不用 DOM `.click()` 模拟用户触发折叠按钮。对话内部的手动展开与教学展开应只有一个状态来源。

目标未挂载或动画未稳定时不显示悬空箭头、不把整个编辑器误认成目标；短暂准备后仍找不到时展示「重新定位」和「退出引导」，保留步骤。目标变化只影响呈现，不能触发发消息或播放。

保持 `ONBOARDING_GUIDE_VERSION = 2`、案例版本、内容校验值和持久字段兼容；仅移动布局变化无需把用户已完成状态作废。

- 本地瞬时状态：代码窗口是否打开、差异是否展开、完成页对比是否展开。不存进音乐会话，不作为练习完成的事实。
- 持久事实：`originalHeard`、`delivered`、`adaptedHeard`、语义 step、会话绑定，继续使用现有结构。
- `view-change` 与 `done` 在手机共享结束画面，在桌面仍对应原来的两步。不要根据移动端 1～4 索引反向覆写语义 step。
- 桌面进行到 `view-change` 后改成窄屏：显示移动完成面板；再变宽：回到桌面对应步骤，不丢失已听标记。
- 换一台设备仍按当前本地存储机制处理，不在此功能中宣称或新增服务端同步。

### 6.2 开发者人工验收矩阵

至少覆盖：

- 320／360 CSS px 短屏与常见 390～440 CSS px 竖屏；宽度越过 460 px 的横竖屏切换。
- iOS Safari 与 Android Chrome；地址栏展开／收起、底部安全区、键盘曾打开后再进入引导。
- 中文与较长英文、浅色与深色、系统大字体／页面放大、减少动态效果。
- 首次邀请、稍后再说、手动重启、中断恢复、模拟音色失败／弱网、切后台。

验收问题：

1. 用户能否找到真实入口，并在一次代码窗口往返后完成余下流程？
2. 提示是否挡住真实播放、发送、关闭或回复内容？操作是否能稳定用拇指点中？
3. 发送示例是否不用键盘；进入自由创作后键盘与输入是否正常？
4. 改编试听是否始终从 0 开始，普通手机扬声器能否在 5 秒内听清新增琴音？
5. 可选差异是否容易收起，结束后是否仍是改编版而非原版？
6. 旋转、中断、退出和重开是否无重复消息、无意外自动播放、无困住用户的遮罩？
