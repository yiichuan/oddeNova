# 始终落库最新代码,哪怕它无法播放

## 决定

`commitPlayback`(见 [CONTEXT.md](../../CONTEXT.md) 的 Playback commit)在 play 一段代码后,**无条件**将其写入 session 存档(`setCurrentCode`),不论 play 返回成功与否。落库的始终是最新代码。

## 背景与理由

同一段代码存在两份:strudel 的"在播代码"(live)与 session 的"存档代码"(持久化)。早期 agent 路径只在 play 成功时才落库,rewind 路径却无条件落库——两处失败语义不一致,且会让两份代码发散(在播为空/报错,存档却是另一版)。

我们统一为**始终落库最新代码**:一致性(两份不发散)优先于"不保存跑不起来的代码"。代码能否播放是运行时的瞬时状态;存档应忠实反映用户/agent 最后产出的代码,运行时错误通过聊天里的报错消息单独告知,而不是靠"不落库"来表达。

## 后果

- play 失败时,存档会保存这段当前跑不起来的代码;用户仍会在对话里看到运行时报错。这是**有意为之**,不是 bug。
- 因此:**不要**给 `commitPlayback` 加"play 成功才落库"的门禁——那会重新引入发散。若将来要改这条规则,请先更新本 ADR。
