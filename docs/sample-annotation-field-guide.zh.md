# oddeNova 采样标注字段规则

**分享版 · 2026 年 11 月 7 日**
**适用版本：类别已知使用 v2.1；类别未知使用 v2.0。**

## 1. 用途与标注单位

标注用于帮助 oddeNova 根据乐器角色和听感选择采样，也供专业听者逐项纠正。基本单位是一个实际音频文件。同一名称下的音高、力度、奏法或音色变体保留各自身份，再整理名称级共性与差异。音频内容哈希相同的文件可以复用听感初标，各自的类别与播放映射分别保存。

目录信息、模型听感和人工确认结果各有来源。模型初标经过结构校验后可以参与软排序；专家确认结果优先使用。结构校验只检查格式、枚举和约束，听感准确性需要人工审核。

## 2. 类别处理规则

| 情况 | 目录类别 | 模型输出 | 选样时如何使用 |
| --- | --- | --- | --- |
| 有明确目录依据 | 保存类别及依据 | `schema_version` 为 `2.1`，省略整个 `source` 对象 | 使用目录类别筛选，使用听感字段比较候选 |
| 目录类别未知或含糊 | 保持为空 | `schema_version` 为 `2.0`，提供 `source` 候选 | 候选进入复核队列，确认后再采用 |

目录依据可以是明确的乐器目录、声部后缀或经核对的资料。模糊文件名、编号、`misc` 等信息需要继续核实。

类别已知时，摘要、证据和用途说明围绕可听特征撰写，避免继续猜测其他乐器。例如，目录明确为次中音萨克斯时，保留目录类别，模型负责描述气息感、亮度、起音与衰减。出现来源争议时交由人工核查目录与声音。

## 3. 通用填写约定

- 固定选项使用下文规定的英文标识。摘要、奏法、候选名称、理由和听觉观察使用中文。
- `unknown` 表示该维度无法可靠判断。`varied` 表示不同事件或时段之间存在明显变化。
- `not_applicable` 或允许为空的对象 `null` 表示该维度不适用。遇到无法判断的适用维度，使用相应未知选项并记录原因。
- 标签数组为空，表示缺少足够依据选择词表中的标签。数组元素保持唯一。
- 亮度、厚度和尾音档位属于听感描述。亮度和厚度结合可辨类别判断，未经人评校准时用于同类软比较。
- 音高与亮度、响度与厚度、文件长度与尾音分别判断。长时间的乐器共鸣与空间混响也分别判断。
- BPM、根音、调性、时长、采样率、声道数等由可信元数据或专门测量提供。模型描述依据来自实际听感，具体数值测量需要可追溯的工具结果。
- 每条标注针对当前音频，名称级摘要需要参考同组变体后形成。

## 4. 输出字段与可选值

### 4.1 版本与摘要

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `schema_version` | 字符串 | 类别已知固定为 `2.1`，类别未知固定为 `2.0` |
| `summary_zh` | 字符串 | 1–100 个字符，用一句话突出最有区分度的可听特征 |

摘要示意可以是“起音清晰锐利，声音偏亮，尾部快速收住，空间残响少”。避免用品牌、设备、录音来源或未经确认的声源猜测填充摘要。

### 4.2 声源候选 `source`（仅类别未知时填写）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `source.family` | 单选 | 按下表选择最有依据的宽类别 |
| `source.candidates_zh` | 字符串数组 | 最多 3 项，每项 1–30 个字符，按可能性排列；无法辨认时为空数组 |

| 标识 | 中文含义 |
| --- | --- |
| `drums_percussion` | 鼓与打击乐 |
| `plucked_strings` | 拨弦乐器 |
| `bowed_strings` | 弓弦乐器 |
| `winds` | 管乐，主要用于木管等声音 |
| `brass` | 铜管乐器 |
| `keys` | 键盘乐器 |
| `synth` | 合成器声音 |
| `voice` | 人声 |
| `environment` | 环境声音 |
| `foley` | 物体动作或拟音 |
| `mixed` | 多类声音共存且无明显主导 |
| `other` | 可辨但超出现有类别 |
| `unknown` | 无法可靠判断 |

鼓组混音仍可归入 `drums_percussion`。声源候选作为待确认线索保存。

### 4.3 声音结构 `structure`

| 字段 | 可选值与含义 |
| --- | --- |
| `event_form` | `single_event` 单次发声；`repeated_events` 多次重复事件；`phrase` 有组织的乐句；`continuous` 连续背景或纹理；`mixed` 混合；`unknown` 无法判断 |
| `pitchedness` | `tonal` 有可辨音高；`noise_like` 以噪声为主；`mixed` 两者共存；`unknown` 无法判断 |

持续的单音也可以是 `single_event`。音高性与声源类别分别记录。有节奏的乐句是否可以无缝循环，需要另行验证。

### 4.4 音色 `timbre`

| 字段 | 可选值与含义 |
| --- | --- |
| `brightness` | `dark` 偏暗；`balanced` 均衡；`bright` 偏亮；`varied` 有明显变化；`unknown` 无法判断 |
| `body` | `light` 轻薄；`balanced` 适中；`full` 厚实；`varied` 有明显变化；`unknown` 无法判断 |
| `texture_tags` | 最多 4 个质感标签，取值见下表 |
| `distortion` | `not_obvious` 未听到明显失真；`audible` 可听到失真；`unknown` 无法判断 |

| 质感标识 | 中文含义 |
| --- | --- |
| `airy` | 空气感 |
| `breathy` | 气息感 |
| `buzzy` | 蜂鸣或嗡鸣感 |
| `grainy` | 颗粒感 |
| `metallic` | 金属感 |
| `woody` | 木质感 |
| `hollow` | 中空感 |
| `smooth` | 平滑 |
| `rough` | 粗糙 |
| `nasal` | 鼻音感 |
| `raspy` | 沙哑感 |
| `ringing` | 鸣响感 |

质感词用于补充独立信息。明暗、厚薄和长短使用各自的专门字段。`not_obvious` 仅表达当前听感，录音设备及处理链需要其他证据。

### 4.5 包络 `envelope`

| 字段 | 可选值与含义 |
| --- | --- |
| `attack` | `sharp` 起音锐利；`rounded` 圆润；`gradual` 渐起；`varied` 有明显变化；`unknown` 无法判断 |
| `shape` | `decaying` 衰减；`held` 保持；`swelling` 渐强；`abrupt_cutoff` 突然截断；`varied` 有明显变化；`unknown` 无法判断 |
| `tail` | `short` 短；`medium` 中等；`long` 长；`varied` 有明显变化；`not_applicable` 无法分离单个事件尾部；`unknown` 无法判断 |

尾音关注单次事件结束后的听感。突然截断属于 `shape`，尾部的长短属于 `tail`，分别选择。连续纹理或复杂混合素材无法分离事件尾部时，可填 `not_applicable`。

### 4.6 空间感 `space`

| 字段 | 可选值与含义 |
| --- | --- |
| `reverb` | `dry` 干声；`slight` 少量混响；`pronounced` 明显混响；`unknown` 无法判断 |

优先听可辨的空间残响。乐器本体共鸣也会产生长尾，无法区分时填 `unknown`。

### 4.7 演奏与音高运动 `performance`

有可辨的演奏或乐音行为时填写对象，不适用时填写 `null`。对象内字段如下。

| 字段 | 类型或可选值 |
| --- | --- |
| `techniques_zh` | 最多 3 个中文奏法或发声动作，每项 1–30 个字符；无法确认具体奏法时可为空数组 |
| `pitch_motion` | `steady` 稳定；`gliding` 滑音；`vibrato` 颤音；`changing_notes` 音符变化；`mixed` 混合；`not_applicable` 不适用；`unknown` 无法判断 |

单个音内部的颤音、滑音与多个音符形成的旋律变化分别辨认。明确的目录奏法作为元数据独立保存，模型填写可听观察。

### 4.8 节奏 `rhythm`

存在多个事件且能够评价节奏组织时填写对象；单次发声填写 `null`。

| 字段 | 类型或可选值 |
| --- | --- |
| `pulse` | `regular` 规则脉搏；`irregular` 不规则；`unclear` 脉搏不清楚 |
| `feel_tags` | 最多 3 项，可选 `straight` 平直、`swung` 摇摆、`syncopated` 切分、`sparse` 稀疏、`dense` 密集 |

同一条节奏标签中，`straight` 与 `swung` 互斥，`sparse` 与 `dense` 互斥。缺少依据时标签数组可为空。

### 4.9 编曲用途建议 `usage_suggestions`

最多 3 项，相同角色保持唯一。允许为空数组。每项包含以下字段。

| 字段 | 规则 |
| --- | --- |
| `role` | 从下表选择建议角色 |
| `reason_zh` | 1–80 个字符，说明哪种可听特征支持该建议 |

| 标识 | 建议角色 |
| --- | --- |
| `low_end` | 低频基础 |
| `backbeat` | 反拍 |
| `pulse` | 节奏脉搏 |
| `melody` | 旋律 |
| `harmony` | 和声 |
| `pad` | 铺底 |
| `accent` | 重音或点缀 |
| `fill` | 加花 |
| `transition` | 过渡 |
| `texture` | 纹理 |

用途随音乐上下文变化，作为建议保存。当前无需强制填写情绪或流派标签。

### 4.10 复核信息 `review`

| 字段 | 规则 |
| --- | --- |
| `uncertainties` | 最多 12 项。每项为 `field` 与 `reason_zh`，原因 1–100 个字符 |
| `evidence` | 最多 5 项。每项为 `fields` 与 `observation_zh`；关联 1–5 个字段，观察 1–120 个字符 |

`field` 和 `fields` 使用精确路径，例如 `timbre.brightness`、`envelope.tail`、`space.reverb`。路径可以引用摘要、结构、音色、包络、空间、演奏、节奏和用途字段。类别未知的 v2.0 还允许引用 `source.family`、`source.candidates_zh`；类别已知的 v2.1 移除这两条路径。

观察应写实际听到的现象，例如“主击后仍能听到独立的空间尾声”。模型报告的依据同样需要听审，空的不确定性数组也需要经过人工确认后才能视为已审核。

## 5. 格式与人工复核

模型输出为一个 JSON 对象。各字段按相应版本的 Schema 保持完整，额外字段需经过版本变更。未知判断使用规定选项；未知或未识别的词不能自行扩展成新枚举。

结构校验失败进入复核清单，相关听感暂停用于选样排序。人工复核优先关注以下情况。

1. 目录类别与声音存在明显争议。
2. 起音、衰减或混响描述与实际试听不符。
3. 同一名称的变体差异被总描述掩盖。
4. 同一声音的多次描述相互矛盾。
5. 枚举越界、必填字段缺失或互斥标签同时出现。

人工纠正时保留原始模型记录，并记录修订版本与审核人。可分别纠正某个字段，无需因来源猜测错误而否定所有听感，也不能仅凭类别一致就确认其他字段正确。

## 6. 程序元数据与选样接口

程序记录文件身份、采样库、合法调用名称、原始路径、音频 SHA-256、音高映射、数组变体位置、类别依据和可调用状态。调用日志另外保存模型、请求配置、原始响应、用量及校验结果。

过短音频遇到接口拒绝时，可以只在提交端补足尾部静音，并记录原音频哈希、提交音频哈希及转换方式。听感描述关注实际发声，补加静音另行记录。

选样时提供合法采样名、目录类别及以下结构化听感。

- `structure` 判断素材形态及音高性。
- `timbre` 比较亮度、厚度、质感和失真。
- `envelope` 比较起音、变化形态和尾音。
- `space` 比较混响感。

同时返回标注状态。`model_initial` 表示模型初标，`expert_confirmed` 表示专家确认，`unavailable` 表示暂缺可用标注。未知声源候选、自由描述、用途建议和审核证据保留在标注资料中，按复核情况决定后续如何采用。

## 7. 类别已知的输出示例

以下是用于说明结构的虚构示例，需依据实际音频填写。

目录元数据独立保存为“电子军鼓”，模型输出如下。

```json
{
  "schema_version": "2.1",
  "summary_zh": "起音清晰锐利，声音偏亮，尾部快速收住，空间残响少。",
  "structure": {
    "event_form": "single_event",
    "pitchedness": "noise_like"
  },
  "timbre": {
    "brightness": "bright",
    "body": "balanced",
    "texture_tags": ["grainy"],
    "distortion": "not_obvious"
  },
  "envelope": {
    "attack": "sharp",
    "shape": "decaying",
    "tail": "short"
  },
  "space": {
    "reverb": "dry"
  },
  "performance": {
    "techniques_zh": ["单次敲击"],
    "pitch_motion": "not_applicable"
  },
  "rhythm": null,
  "usage_suggestions": [
    {
      "role": "backbeat",
      "reason_zh": "清晰起音与短尾音可以为反拍提供紧凑的落点。"
    }
  ],
  "review": {
    "uncertainties": [],
    "evidence": [
      {
        "fields": ["envelope.attack", "envelope.tail"],
        "observation_zh": "敲击开始清楚直接，主击后很快安静下来。"
      }
    ]
  }
}
```

## 8. 类别未知时的附加结构

类别未知时，将版本改为 `2.0` 并加入 `source`。下面只展示附加字段，其余字段仍按完整结构填写。

```json
{
  "schema_version": "2.0",
  "source": {
    "family": "drums_percussion",
    "candidates_zh": ["小型金属打击乐", "物体敲击"]
  }
}
```

这份文档描述当前字段契约。调整字段含义、枚举或适用规则时，应同步升级版本、校验器、标注提示词与人工说明。
