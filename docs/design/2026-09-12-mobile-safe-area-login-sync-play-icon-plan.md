# 移动端安全区、多设备登录同步与桌面播放图标修改方案

日期：2026-09-12。状态：方案，尚未实施。

本次只新增本文档，不修改代码、数据库、部署配置或线上账号设置。以下基于当前源码；旧文档 `mobile-chrome-and-tilt-followup-plan.md` 中已有部分实现，本方案处理其仍然存在的缺口，不重复按旧方案重建模块。

## 1. 目标与范围

1. 手机登录界面的中灰遮罩背景、登录后的浅灰对话背景、精选背景以及深浅主题切换，都能及时更新页面安全区底色与浏览器主题色提示。
2. 同一账号手机、电脑可同时使用。电脑登录不因游客历史导入失败而被阻塞，历史不丢失、不重复导入、不覆盖较新的云端内容。
3. 仅桌面工作室对话中的代码 widget，右侧播放 icon 改成描边 Play，保留播放中的停止图标和现有交互。

实施优先级：历史同步 → 安全区颜色 → 图标。三项可以独立验收。

## 2. 移动端安全区背景

### 已确认的代码缺口

| 位置 | 当前行为 | 影响 |
| --- | --- | --- |
| `src/lib/browser-chrome-color.ts` | 已统一写入 `theme-color` 与 `--browser-chrome-color`，支持 studio / featured、精选染色和代码遮罩 | 应扩展现有实现，无需新增第二套控制器 |
| `src/App.tsx` 的 `useBrowserChromeColor` 调用 | 只传页面、精选染色和 `codeSheetOpen || favoritesCodeOpen` | 未纳入欢迎、账号登录和历史同步遮罩 |
| `src/lib/appearance-preferences.ts` 的 `applyTheme()` | 每次主题切换都调用 `applyBrowserChromeColor('studio', resolved)` | 精选等状态被暂时覆盖成工作室色，并清除遮罩、染色参数 |
| `src/hooks/useBrowserChromeColor.ts` | 在 `useEffect` 中按页面状态修正颜色 | 存在页面提交与颜色修正的时序间隔 |
| `src/index.css` | 手机根背景有 240ms 颜色过渡，meta 直接切色 | 两个颜色输出在过渡期间不同步；460px 以上不使用安全区变量 |

登录的中灰不是独立页面底色，而是 `WelcomeModal` / `AccountModal` 使用 `--color-overlay-backdrop` 叠加页面的结果。不能仅凭 `auth.user` 决定登录背景是否存在，要按实际可见遮罩计算。

这些缺口可以从源码确认，但尚未在用户手机上复现持续不更新的现象；不能据此认定全部原因已找到，也不能把浏览器采样或缓存当作已确认根因。

### 推荐方案：当前可见背景由一个控制点管理

继续使用 `browser-chrome-color.ts`，将输入明确为：当前页面、已解析主题、精选染色、实际可见遮罩。由它同时更新根元素 CSS 变量和 meta。

1. **主题更新不再重置页面。** 控制点保存当前背景上下文；启动、尚未注册页面时可默认 studio。后续 `applyTheme()` 更新主题后，按已保存上下文立即重算，不经过 studio 中间色。页面、染色和遮罩变化由 App 的唯一入口更新上下文。
2. **补齐遮罩状态。** 使用与 JSX 相同的显示条件：欢迎窗口为 `welcomeOpen && !auth.oauthErrorKey && !auth.user`；账号窗口为 `accountOpen || auth.oauthErrorKey`；现存历史同步遮罩为 `guestImportSessions`。实施第 3 节取消同步阻塞弹窗后，移除该项，不能留下已隐藏的遮罩状态。
3. **区分遮罩材质。** 将仅表示代码窗口的 `dimmed` 扩展为有明确类型的遮罩描述。账号/欢迎窗口使用 `--color-overlay-backdrop` 对应的 RGBA，代码窗口沿用现有 scrim。按实际图层从下至上合成；一个遮罩只计算一次。如果两个真实遮罩同时显示，就按实际叠加，不能简单按多个 open 标志重复压暗。
4. **颜色与页面同一次视觉提交生效。** 页面上下文更新采用 `useLayoutEffect`，处理首次渲染、导航和弹窗开关；主题路径同步重算。不要在 hook 清理时恢复 studio，以免 effect 重放或快速切换闪色。
5. **取消根背景固定 240ms 过渡。** 本次以及时到达目标色为准，根背景与 meta 均直接切换。保留页面内部光效动画，不新增逐帧 meta 写入或 WebGL 采样。
6. **覆盖手机横屏与恢复。** 根 canvas 使用统一变量，不依赖仅 460px 以下才启用的规则；桌面内容仍由自身容器绘制，验收其外观。处理 `pageshow` 和恢复可见时重新应用当前上下文，监听由单一入口注册并清理。

初始页面底色沿用当前值：studio 深色 `#0D0D0D` / 浅色 `#F7F7FA`，featured 深色 `#05070a` / 浅色 `#DEDEE0`。保留精选封面边缘染色。遮罩参数应与 CSS token 共源，避免另抄一组登录“中灰”色值。

不采用“每个页面分别写 meta”或“延迟若干毫秒再强刷”的方案：前者会增加写入竞争，后者无法覆盖主题、登录和浏览器恢复的不同顺序。

### 浏览器边界与验收

网页能控制 document canvas 和提供主题色建议，不能强制所有系统工具栏逐帧采用指定颜色。`theme-color` 是浏览器采用的建议颜色，兼容性应按实际版本确认；`viewport-fit=cover` 和安全区 inset 解决页面延伸与内容避让，不等于直接控制系统栏。[MDN：theme-color](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/theme-color)、[WebKit：安全区设计](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)。

自动化覆盖现有 `browser-chrome-color.test.ts`、`useBrowserChromeColor.test.tsx`、`appearance-preferences.test.ts` 和 App 对应用例：

- 登录遮罩出现/关闭；登录成功但账号窗口尚未关闭；欢迎与账号窗口切换。
- 对话 ↔ 精选、详情染色、代码窗口开关、深浅模式和跟随系统主题。
- 切主题过程中不写入错误的 studio 中间色；最终 meta 与 CSS 变量一致。
- 首次挂载、effect 重放、页面恢复及监听清理。

实施后由开发者真机验收 iOS Safari 与 Android Chrome，记录系统/浏览器版本；覆盖竖横屏、工具栏展开收起、键盘弹出收起、后台恢复、登录和导航往返。若应用输出正确而系统栏仍滞后，再针对该浏览器版本调查，不继续盲加定时器。通过标准：应用自身安全区没有旧页面残色，支持着色的系统栏能随状态更新，无需刷新；渐变与纯色之间允许现有近似，不要求像素完全一致。

## 3. 手机已登录后，电脑登录出现“本机历史同步失败”

### 已确认的链路与尚未确定的根因

当前链路是：账号恢复 → 读取电脑的 guest IndexedDB → `importGuestSessions()` → `useSessions.importSession({ awaitCloud: true })` → 写账号本地副本 → `checkpoint()` → `flush()` → 成功后删除 guest 原件。

- `src/App.tsx` 的 `cloudLibraryEnabled` 依赖导入 gate、`guestImportSessions === null` 和未在导入，因此本机导入会挡住正常云端历史加载。
- 首次失败仍展示阻塞弹窗；现有“稍后再说”和第二次失败退出只解决卡住，没有解决失败本身。
- 错误仅用 `isOnline()` 分成 offline / rejected。网络请求、登录态、本地存储、服务端校验与清理失败可能显示成同一条错误。
- `checkpoint()` 会吸收部分错误并安排重试，不能将其 resolve 当作云端写入确认；`flush()` 才可能继续抛出失败。`importGuestSessions()` 的错误范围还包含成功上传后的 guest 删除失败。
- `importSession()` 保留合法 UUID，并覆盖账号本地同 ID 会话；`api/sessions.ts` 使用全局 `id` upsert。重复导入有覆盖旧/新内容的风险，但不能据此推断两个独立设备一定发生 UUID 碰撞。
- 本地配置没有证明存在“只允许一台设备登录”的限制；线上鉴权设置、实际 HTTP 状态和数据库错误尚未读取。**“手机已登录”是复现场景，不是已证实的根因。**

### 推荐方案：后台可靠导入，登录与云端历史独立可用

**A. 先取得可以归因的失败证据。**

复现“手机保持登录 → 电脑有游客历史时登录同账号”，并与电脑无游客历史、手机退出后的场景对照。记录导入阶段（读取/归一化/本地持久化/上传/guest 清理）、请求状态、稳定错误码、请求关联 ID及账号切换时间。日志不记录 token、聊天内容或完整上传体。

核对线上鉴权是否配置单设备会话限制，但不预设需要改配置。将 API 当前统一 500 的数据库失败按可识别原因映射为稳定错误码，供客户端区分鉴权、格式校验、冲突和可重试服务错误；不要向用户直接展示数据库错误文本。

**B. 移除登录对本机导入完成的依赖。**

账号确认后，在保留必要账号初始化检查的前提下打开云端历史加载。guest 检查/导入进入独立后台任务，不再用全屏同步弹窗阻塞导航、阅读或创作。显示非阻塞状态“正在同步本机历史”；暂时失败时显示“本机历史已保留，联网后继续同步”，附适合该错误的重试入口。永久失败应明确提示需处理，不能永远显示“正在同步”。

只移除弹窗会掩盖问题，因此以下持久化和恢复机制是这一修改的组成部分。

**C. 导入必须持久化、幂等且绑定账号。**

- 建立持久化导入记录，以 `(目标 userId, 来源 guestId)` 为去重键，保存稳定的目标 UUID、内容版本/指纹及阶段（待上传、待清理、完成/需处理）。本地副本和待上传记录应在同一 IndexedDB 事务中落盘。
- 同一来源对同一账号重试使用同一目标 ID；对另一账号采用独立目标映射，不能复用已归属其他账号的 ID。
- 兼容旧流程已上传但仍有 guest 原件的情况：先核对本账号同 ID 云端内容。内容一致则确认上传完成并补做清理；内容不同或无法安全确认来源时保留为独立导入副本，不把旧 guest 内容覆盖到已有会话。普通云端会话无需在本次全面重构成协同编辑系统。
- 上传成功与 guest 删除分成两个阶段。清理失败只重试清理，不重复上传；未确认成功前保留 guest 原件。
- 利用现有 dirty marker 和同步队列，补齐导入阶段记录，不建立竞争写入的第二套上传队列。重新加载后恢复未完成任务；内存降级无法持久保存时不要显示“已持久保存”或删除唯一 guest 数据。
- 任务启动时捕获 owner / userId；退出或换账号时取消/废弃旧任务的 UI 回写。旧账号结果不得设置新账号 gate、修改其列表或触发来源清理。恢复任务只针对当前账号。
- 同一浏览器多标签并发导入时，通过唯一键和事务复用映射，避免创建两个目标；一个页面内的 ref 防重不足以覆盖此情况。

**D. 重试按原因处理。**

网络/超时/可恢复服务错误采用有上限的指数退避和联网恢复；请求需有超时，避免单项永久占住任务。401 仅在确认仍是同账号后进行一次受控会话刷新并重试，持续无效再提示本设备重新登录；校验、权限或明确不可恢复错误暂停自动重试，保留数据并给出操作入口。不要让电脑的失败触发手机退出，也不要调整现有本地范围登出语义。

导入产生的本地摘要与并行到达的云端列表按目标 ID 合并，晚到的云端响应不能清掉待上传项；用户在导入副本上继续编辑时，旧任务快照不能回写覆盖新内容。

### 涉及文件

主要为 `src/App.tsx`、`src/lib/session-import.ts`、`src/lib/session-storage.ts`、`src/hooks/useSessions.ts`、`src/lib/session-cloud-sync.ts`、`src/services/cloud-session-repository.ts`、`src/lib/i18n.ts`。错误归因涉及 `api/sessions.ts`；鉴权刷新仅在复现证据支持时调整 `src/services/auth-service.ts`。持久化导入记录需要 IndexedDB schema 升级及旧数据兼容。线上认证配置、数据库策略仅在定位到确实不符合多端使用目标时另行明确变更内容。

### 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 手机在线，电脑没有游客历史后登录 | 直接读云端历史，两端均保持可用 |
| 手机在线，电脑有游客历史后登录 | 可立即使用工作室；后台导入，成功后另一端重新加载可见 |
| 导入时离线/超时，随后恢复 | 无阻塞弹窗；数据保留；有限重试并完成 |
| 上传成功但 guest 删除失败；上传响应丢失 | 重试不重复创建，不覆盖新内容，能恢复正确阶段 |
| 刷新页面、退出后重登、连续点重试、多标签并发 | 每个来源/账号只有一个稳定目标 |
| 导入中从账号 A 切到 B | A 的结果不污染 B；原件不会被错误清理 |
| 导入 ID 已存在且云端内容更新 | 保留新内容，必要时独立导入副本 |
| 部分历史坏数据或权限失败 | 其余项继续；坏项可定位、可恢复、不无限重试 |
| 本地写入失败或仅内存降级 | 不误报已安全保存，不删除唯一来源 |
| 仅 guest 清理失败 | 提示为清理阶段问题，不再报上传失败 |

运行上述模块现有定向测试并补充这些数据安全路径，配合相关 TypeScript / lint 检查。同步方案横跨账号、存储、请求与 App，落地完成后属于较高风险变更，应再运行完整测试与生产构建；这不是本次文档任务要执行的检查。

## 4. 桌面工作室代码 widget 播放图标

`src/components/icons.tsx` 已提供 `PlayOutlineIcon`。`CodeDiffView.tsx` 的版本代码 widget 和 `ConversationView.tsx` 的兼容代码块按钮目前使用填充 `PlayIcon size={13}`。

推荐复用 `PlayOutlineIcon`，保持尺寸、颜色、按钮大小、播放/停止回调、禁用条件和 aria-label。只在桌面工作室对话上下文选择描边版：从现有桌面 `Sidebar` 调用路径传递明确外观参数，经 `ConversationView` 下发到 `CodeDiffView`；移动端沿用默认外观。兼容代码块路径同样处理，避免新旧历史的图标不同。

不全局修改 `PlayIcon`；不修改工作室右侧 `CodePanel` 播放控制，也不修改精选、收藏的 `ArchivedConversationView`。播放中仍使用现有 `StopIcon`。

验收：桌面对话的折叠/展开 widget、新版本记录/旧代码块均显示空心三角；播放对应版本、切换停止状态仍正常，移动端及其他页面不变。检查局部 diff，必要时运行现有 `ConversationView` / `CodeDiffView` 的定向测试；不单为 SVG 填充变化新增整套测试或单独跑全量构建。
