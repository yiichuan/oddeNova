# oddeNova 新手操作指引方案

日期：2026-09-30

状态：产品与实现方案；尚未制作 mock 音乐、实现交互或完成听感验收。

## 1. 目标与范围

用户完成注册／登录、进入工作室后，通过一次预设改编练习，学会「播放音乐 → 发送创作要求 → 试听变化 → 继续创作」。目标体验时长约 1～2 分钟，不以倒计时约束用户。

第一版只有一条必经练习，不提供多个音乐方向，不要求学习代码、导出、分享或收藏。练习的回复与改编代码均预制，不调用模型、不运行 agent loop、不消耗模型额度；声音由真实 Strudel 引擎播放。完成后明确切换到真实 AI 创作。

## 2. 印象曲检查与音乐设计依据

基准为 `themes/beta-1.0/theme.zh.strudel.js`，英文版本仅注释语言不同；当前入口为 `src/lib/theme-song.ts`。

代码可确认的事实：

- 全局速度为 `setcps(0.4)`，一个 cycle 为 2.5 秒。本文时间以从乐曲起点播放计算，不包括音色加载时间。
- `horizon` 全程存在，使用 `gm_pad_warm`，承担持续和声背景，不能为了入门演示把全曲的铺底替换成短音。
- 和弦音组为 `[d3,a3,c4,e4] → [g3,b3,d4,e4] → [c3,g3,b3,d4] → [a2,e3,g3,d4]`，每组持续两个 cycle，即 5 秒；音乐设计以实际音符为准。
- 前 10 秒主要是 `horizon` 和 `wind`。`footsteps`、`earth`、`wandering_light` 的 mask 在前四个 cycle 关闭，约第 10 秒进入。
- `nova_theme` 也使用 `gm_epiano1`。选用同类音色可以呼应原曲后续主题，同时仍需单独调整音区、包络和响度。

据此放弃「把 horizon 整层改成逐音演奏」。采用「保留原铺底，在开头叠加与其和声一致的短音声部」：差异集中在最容易试听的开场，后续编排保持原样。

这些是代码分析与制作约束，并非已经确认好听。最终预设必须通过第 10 节的实际试听验收。

## 3. 唯一预设指令与改编策略

### 用户发送的指令

> 保留原来的背景和弦，只在开头 10 秒加一串清脆的电钢琴音符，跟着和弦一颗颗弹出来。

面向新手不要求输入 `horizon` 等标识，回复和可选详情再建立声音与音层的联系。

### 制作策略

保留原 `horizon` 的音符、音色、音量、滤波、声像、混响和节奏，不改速度，也不修改其它原有音层。新增一个独立命名的 `horizon_intro` 音层，仅承担开头装饰。界面称为「开场电钢琴」，并说明它跟随「背景和声 horizon」。

独立音层便于差异检查、试听和后续真实 AI 修改。准确的结果描述是「保留原有音层，新增 1 个开场音层」，不能显示「只修改了 horizon」或高亮一段实际没有改动的原代码。

| 音乐时间 | 铺底保持的实际音组 | 新增短音声部的制作起点 |
| --- | --- | --- |
| 0～5 秒 | D、A、C、E | 从 D4、A4、C5、E5 的逐音排列开始制作，沿用原和声音级，不引入额外和声走向 |
| 5～10 秒 | G、B、D、E | 从 G4、B4、D5、E5 的逐音排列开始制作，在第 5 秒与铺底同步换和弦 |
| 10 秒以后 | 原曲继续运行 | 不再触发新增音符；短尾音自然结束，原曲音层继续进入 |

具体制作约束：

- 初始节奏为每个 cycle 四个短音，间隔约 0.625 秒；0～5 秒足以听见完整音型的重复。试听后允许在同一和声音级内优化排列和音区，最终配置与说明一起冻结。
- 使用 `gm_epiano1` 作为首选，设置清晰起音、短衰减和较少混响，不使用长延迟；目标是能辨认单颗音符，同时保留印象曲的柔和感。
- 新增声部以节奏轮廓和音色获得辨识度，不靠明显抬高总音量。音量、滤波及包络数值在制作时通过试听确定，不在本方案中假定一个必然合适的 gain。
- 最后几颗音符适度收束；安排足够的释放空间，目标在第 10 秒附近自然交给进入的其它声部，避免硬切产生点击声。
- 时间门控只覆盖从乐曲起点算起的前 10 秒。不能直接使用每 32 个 cycle 重复一次的开场 mask，否则新增声部会在约第 80 秒再次出现。用户从头重播时才重新播放开场。
- 不对完整乐曲调用全局加速、改调或替换铺底；不开启影响其它音层的共享效果参数变化。
- 最终完整脚本应验证新增音层在定位、重播和长时间播放时的门控语义，不以注释代替验证。

### 预设回复

> 已保留原来的背景和弦，并在开头 10 秒加了一串电钢琴音符。它跟着原来的和弦逐个弹奏，随后退场。
>
> 听 **0～5 秒**：原版主要是铺开的背景声，改编版会多出一颗颗清晰的琴音。

附加信息：

- 「新增：开场电钢琴」
- 「原背景和声保留」
- 「查看修改」展开 `horizon_intro`，并可定位参照层 `horizon`。

精确退场文案以最终听感验证为准：10 秒是停止新增音符的边界，不承诺所有混响在这一刻绝对消失。

## 4. 完整用户流程

### 进入条件与邀请

保留现有首次欢迎／注册登录流程。在鉴权、会话恢复、游客数据处理结束，用户进入可操作的工作室后，展示一张邀请卡，避免与其它弹窗叠加。

> **听见你的第一处改变**
>
> 不用懂乐理，也不用写代码。先听一段音乐，再试着为它加上一串琴音。
>
> **开始体验**　稍后再说

点击开始后，从固定基准印象曲建立独立练习会话「我的第一次创作」，保留已有会话和草稿，不覆盖用户原来的印象曲。反复点击或恢复流程不得重复创建会话。

### 第 1 步：听原版

- 提示：「先听开头 5 秒，留意铺开的背景和弦。」
- 高亮播放入口，提供「听原版 · 0～5 秒」。
- 必须由用户手势启动真实播放。等待所需音色就绪后才开始计算试听进度。
- 原版片段播放结束后进入下一步；中途暂停保留状态，允许重听或明确跳过。不用“按钮被点击”冒充成功试听。

### 第 2 步：发送创作要求

- 提示：「告诉 oddeNova，你希望音乐发生什么变化。」
- 显示唯一的预设指令。点击「填入这句话」后放入真实输入区域，由用户亲自点击发送。
- 练习期间只接受这个预设，输入内容不可任意改写；仍保留明确的「自由输入」入口，点击后退出预设流程并说明将使用真实 AI。
- 输入区域持续标注「新手练习 · 预设示例」，不把固定回复伪装成现场生成。
- 发送后显示「正在载入示例改编」，约 1～2 秒内短暂呈现预制回复并载入结果。不仿造长推理过程，不制造虚假工具执行日志。
- mock 期间禁用重复提交，允许退出；退出后取消尚未完成的演示任务，不能继续往其它会话写结果。

### 第 3 步：听出差别

- 展示第 3 节的预设回复，并指向两个按钮：「听原版 · 0～5 秒」「听改编 · 0～5 秒」。
- 提供「连续对比」：原版 5 秒 → 短暂停顿／清理尾音 → 改编版 5 秒，清楚显示当前版本。
- 引导语：「背景和弦还在。留意新版多出来的一颗颗琴音。」
- 推荐试听区间始终是两版相同的 0～5 秒，不从发送消息或音频加载开始计时，不在当前播放位置随意接播另一版。
- 改编片段成功播放完后显示「听到了，继续」。用户也可点「再听一次」；未完整播放可明确跳过，不能统计为已完成试听。
- 可选「听完整开场 · 0～12.5 秒」，用于听见第 5 秒换和弦和第 10 秒附近的交接，不作为必经步骤。
- 「查看修改」为可选，不要求用户读懂代码。

### 第 4 步：转入自由创作

> **你已经完成第一次改编**
>
> 先说出想法，再听听变化，就能一步步做出自己的音乐。练习作品已保留在历史中。
>
> **继续改这首**　创作一首新的

- 保存成功后才显示“已保留”；持久化不可用时改为「你可以继续改这首」，并显示真实保存状态。
- 明确补充：「刚才使用的是预设示例。接下来会由 AI 实际生成，通常需要更长时间。」
- 「继续改这首」使用改编后的完整代码作为当前草稿，解除预设输入限制；「创作一首新的」建立普通空白会话。
- 原版对比试听不得意外把最终工作草稿改回原版；退出对比时恢复改编版为当前草稿。
- 练习的状态文字、引导卡和模拟进度不进入真实模型上下文；真实接续只使用有效的用户指令、结果说明和当前代码。

## 5. mock 资产与执行策略

每个案例维护为一套版本化资产。本版只制作一个案例，例如 `intro-piano-v1`。

| 字段／资产 | 用途 |
| --- | --- |
| 案例版本、引导版本、基准曲版本及内容校验值 | 保证原曲、改编结果、文案与进度匹配 |
| 原版脚本引用 | 直接引用归档的 beta-1.0 文件，不在 src 中手工复制另一份原曲 |
| 完整改编脚本 | 预先制作、试听、验证后保存；运行时直接载入，不依赖临时字符串替换 |
| 中英文预设指令与回复 | 两种语言对应同一音乐结果 |
| 变更元信息 | 新增 `horizon_intro`，参照 `horizon`；原有音层保持原样 |
| 试听窗口 | 必经 0～5 秒，可选 0～12.5 秒；新增触发范围 0～10 秒 |
| 轻量演示事件 | 载入中、回复出现、结果就绪；不是模型工具调用记录 |
| 音色依赖与验收记录 | 原版／新版所需资源、实际验证过的播放与衔接结果 |

已发布主题曲目录属于历史，不修改其原始文件；新增教学资产使用独立目录。升级印象曲时制作／验证对应案例，不把旧案例直接应用到新基准或用户已经编辑的代码上。

项目现有 `src/demo/demo-llm.ts` 虽然使用脚本化响应，仍通过 agent loop 执行，不直接用作这次新手引导入口。新增独立的预设演示控制器，复用现有消息展示、会话版本、代码查看与播放能力，绕过模型与 agent loop。

## 6. 声音对比与代码定位

- 音频统一通过现有 `useStrudel`／引擎生命周期控制，不在引导组件新建 AudioContext。
- 开始对比前准备两版资源；一次只播放一个版本。处理前一段的延迟、混响和结束淡出，避免两版叠响。
- 片段结束做短淡出，避免硬截断；两版使用一致的试听处理，不额外增强改编版。
- 保持原有声部增益一致，新增声部留出余量；检查总体响度与峰值，不以明显更响作为差异来源。
- 优先在整曲混音中完成听辨，不能必须静音原铺底才能听到新增琴音。
- 代码定位使用音层标记，不依赖行号。展示新增音层的实际差异，参照原铺底时标注「保持原样」。
- 桌面端在代码区定位高亮；手机端打开局部差异面板，不强制切到整页代码编辑器。

## 7. 展示、触发与恢复规则

### 展示形式

局部高亮、短提示卡和四步进度。桌面卡片靠近控件，手机端采用避开键盘和播放控件的底部卡片。每步保留跳过／退出入口；播放按钮能用键盘操作，焦点不被遮罩困住。尊重减少动态效果偏好。

### 首次触发

- 新手状态独立于 `oddenova_welcome_seen` 和主题曲 seed 标记，欢迎出现过不代表练习完成。
- 新账号首次进入工作室自动邀请；上线前已存在的账号默认不自动弹出，提供「更多 → 新手指引」。不能只凭出现了系统印象曲就判断用户已经创作过。
- 分享、嵌入、导入、密码恢复等入口先完成原任务，不强制切换到练习。
- 完成或明确跳过后不再自动弹出，可手动重启；「稍后再说」不立即重弹，保留手动入口。

### 持久化与中断

- 状态按账号隔离，建议同步账号级完成／跳过状态；本地缓存用于即时恢复。记录引导版本、案例版本、步骤、练习会话 ID、原版／改编版记录 ID。
- 未完成就刷新时，展示「继续上次练习」入口，不自动开始播放；根据实际已保存的回复和版本恢复，不能重复插入结果。
- 切账号、退出登录、切会话、离开工作室或卸载时取消待执行演示，停止练习试听；迟到结果不得写入新账号或新会话。
- 完成后的练习作品保留。用户在进行中跳过时，删除本次「我的第一次创作」练习，并新建、切换到普通空白会话；不能覆盖当前用户的既有草稿。
- 恢复时练习会话被删除、内容已被用户编辑或资产版本不匹配，说明无法接着演示，提供重新建立练习的入口，不覆盖现有内容。

## 8. 状态与异常处理

推荐状态顺序：待邀请 → 原版试听 → 指令待发送 → 载入预设 → 改编试听 → 完成。暂停、稍后、跳过和错误作为明确分支处理。

- 资源加载失败：提供重试，停在当前步骤，不偷偷调用真实 AI 补位。
- 播放受浏览器限制：保留点击播放入口，不能仅靠计时器推进。
- 用户中途停止：可重听或退出，不标记试听成功。
- mock 结果写入失败：保留可恢复状态并提示重试，不重复生成版本；只有代码与回复均保存成功才进入结果就绪。
- 自由创作缺少模型配置或额度：沿用正常产品提示，不让此问题阻断前面的预设练习。
- 当前已有音乐播放：用户选择开始练习／试听时再切换播放，不在邀请出现时突然打断音乐。

## 9. 实现拆分

1. **制作教学音乐资产**：准备完整改编版、差异元信息与试听窗口，先完成音乐验收，再冻结最终文案。
2. **预设演示控制器**：实现可取消的固定事件流程、会话绑定及幂等写入，确保不进入 LLM／agent 路径。
3. **引导 UI**：邀请、四步提示、预设填入与发送、代码定位及移动端适配。
4. **A/B 试听**：两个版本从头播放指定片段，处理加载、尾音、草稿恢复和播放器互斥。
5. **进度与真实创作衔接**：按账号恢复、完成状态同步、手动重启及真实上下文交接。

第一版不扩展多套音乐案例、不实现任意输入的 mock 匹配、不要求分享收藏，也不在本任务中改写主 agent 的系统提示词。

## 10. 验收标准

### 音乐与听辨：上线前必须实际试听

- 代码差异确认：原 `horizon` 和其它原有音层、全局速度均保持原样；仅新增受时间限制的声部。
- 0～5 秒：在整曲混音中，普通手机扬声器和耳机都能辨认新增的逐音琴声；邀请不熟悉曲子的人对比后描述差别。
- 5 秒：琴音随原和弦切换，没有错位或不必要的不协和感。
- 8～12.5 秒：短音自然收束，后续脚步、低音与光点进入清楚，不因新增尾音显得拥挤。
- 试听整首，并跨过 80 秒：新增琴音没有周期性重现，后续铺底、主题和暴雨等编排保持原样。
- 无爆音、削波、突兀硬切，差异不是单纯由总响度提升造成。
- 如果达不到要求，先调整新增声部的音区、包络、音符排列与音量；不为了更明显而破坏原曲铺底。

### 功能与数据

- 引导路径无模型网络请求、无 agent loop；真实创作的第一条请求使用改编结果作为当前代码。
- 能以实际播放成功与进度推进，而非单纯依赖按钮事件和墙钟计时。
- A/B 区间一致，切换不叠响，听原版不覆盖改编草稿。
- 双击发送、刷新恢复、退出后返回不会重复消息、版本或练习会话。
- 覆盖退出、切账号、切会话、音频失败和保存失败等分支。
- 中英文资产的音乐内容一致，差异标记与回复内容真实对应。
- 实现阶段运行与状态机、会话写入、播放控制和音层差异有关的针对性测试；按实际改动范围执行类型／lint 检查。UI 视觉由开发者审阅，不擅自启动开发服务器或浏览器做验证。

### 体验指标

记录邀请展示、开始、原版试听完成、预设发送、改编试听完成、跳过／错误位置、练习完成，以及完成后的第一条真实创作指令。预设发送和 mock 成功不计入真实 AI 创作成功率；不需要收集用户自由输入原文来统计漏斗。

最终成功标准：用户知道原来的背景和弦仍在，能听出新增的琴音，并知道下一次可以通过自然语言继续改变音乐。
