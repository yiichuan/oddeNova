# 本轮检索观察

建议完成盲听后再查看 audit.json、代码及本文件，以免选样信息影响评分。

这些是本轮实际查询回放得到的具体问题，不是听感胜负结论，也不是独立人工标注的准确率。

1. **类别的子串匹配会混淆声部。** `comic-sneaking-0-search` 查询“蹑手蹑脚的低音拨弦”，类别为 `bass`，前三项为 OberheimDMX、BossDR110、MPC1000 的底鼓。原因是目录中的 `bass drum` 也包含 `bass`。
2. **复合类别使用任一词匹配，过滤可能过宽。** `morning-forest-1-search` 的类别为 `打击乐 percussion · Balafon`，返回前三项为 agogo、anvil、ardha，而不是优先限定 Balafon。
3. **自然语言与类别词覆盖不足。** `beach-holiday-1-search` 连续用中文“贝斯”查询得到空结果；`keys`、`lead`、`melodic` 等角色词也有空结果。需要区分同义词缺失和六库确实不覆盖的音源，不能把所有空结果都当作错误。
4. **音色条件可掩盖声源不匹配。** 无类别查询“轻盈明亮的木质拨弦旋律”返回 ocarina_vib、organ_4inch、pipeorgan_quiet；听感特征吻合不等于符合拨弦声源需求。
5. **返回的标注音区不一定是实际演奏音区。** 首次咖啡馆钢琴候选使用 Ds2 文件的标注，实际作品有 D4、F4 等音符。audit.json 的 annotationRootMatches 单独记录这种偏差，不能将低音区听感推广为整件乐器的听感。
6. **静态通过不等于能播放。** 一首太空场景对照作品将 0、4、7 等数值直接交给 note，选中的 GM 音源不支持其中的低音高，渲染失败。保留原代码，不修曲、不补抽样，配对排除出盲听。

候选特征不全部匹配并非自动判错：当前实现将特征作为软排序，未承诺全部满足。目录未知字段与听感模型初标也不能作为可靠的人工真值。建议后续优先修正类别匹配、同义词覆盖和实际演奏音区的关联，再用相同题库复测；本次不修改这些产品行为。
